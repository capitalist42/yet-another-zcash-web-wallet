# Default endpoint is a third-party lightwalletd proxy

The wallet needs a gRPC-Web lightwalletd endpoint and ships `https://zcash-mainnet.chainsafe.dev` / `https://zcash-testnet.chainsafe.dev` (CORS-open, verified live 2026-10-19) as presets. Syncing discloses the wallet's full viewing key and address usage to that operator — the transaction graph is private from us but visible to them — and, inherent to web apps, the deploy host serves the code that holds the unlocked seed. We accept both for v1: the alternative (running our own proxy fleet) reintroduces the backend we refuse to operate. Mitigations: endpoint is a first-class per-network setting with free-text override, a persistent endpoint chip in the UI, one-sentence onboarding disclosure ("your lightwalletd provider can see your activity"), and self-host docs (`lightwalletd-rs --grpc-web`, Envoy/grpcwebproxy recipes). Update/supply-chain risk (host-served JS, pinned-but-unauditable `@zcashlabs/zcash.js` binary) is accepted on the same basis: no client-side mechanism can pin what the origin serves.
