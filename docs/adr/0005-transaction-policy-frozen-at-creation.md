# Transaction policy is frozen at client creation; setting changes = reopen

`zcash.js` rc.5 takes `TransactionPolicy` only in `createWalletClient` and freezes it. There is no per-send or per-propose policy (`ExecuteOptions` = `{ signer? }`; unknown keys are rejected). Expiry, shielding threshold, and transparent spends change only by closing and reopening the client. Sync state is kept, with no "restart required" step. Settings is read before every create, including the first. "Allow transparent sends" is a Settings switch, not a per-send toggle: default off; turning it on adds `'transparent'` to `spendPools` (warning, then reopen). `transparent: 'disallow'` cannot ship, because shielding spends owned transparent inputs. Default is `transparent: 'allow-owned'` everywhere (confirmed in the §0 spike). Direct transparent sends stay behind that switch. Rejected: two open clients to fake a per-send policy — extra RAM, two sync workers, and an invariant to maintain forever.
