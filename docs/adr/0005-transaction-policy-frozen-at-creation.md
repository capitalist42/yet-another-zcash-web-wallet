# Transaction policy is frozen at client creation; knob changes = reopen

`zcash.js` rc.5 accepts `TransactionPolicy` only on `createWalletClient` and freezes it; there is no per-send/per-propose policy carrier (`ExecuteOptions` = `{ signer? }`, unknown keys rejected). So expiry, shielding threshold, and transparent-spend enablement are applied by silently closing and reopening the Client (durable sync state survives; no user-visible "restart required" step). Consequences: "Allow transparent sends" is a Settings-level switch (adds `'transparent'` to `spendPools`, warning + reopen), not a per-send toggle; SDK shorthand's `transparent: 'disallow'` cannot ship as-is because shielding spends owned transparent inputs internally — default is `transparent: 'allow-owned'` app-wide (confirmed in §0 spike), and the UI owns gating direct transparent sends. Rejected: per-send policy emulation by keeping two open Clients — RAM cost, two sync workers, and an invariant we'd have to police forever.
