# Observe-only payment recovery; no automatic rebroadcast

The SDK offers startup auto-rebroadcast of previously-dispatched exact bytes (`RecoveryPolicy.rebroadcast`), and omitting it makes ambiguous submissions (`outcome: 'unknown'`) sit unresolved until someone acts. We run `RecoveryPolicy { mode: 'online' }` observe-only (offline when the endpoint is unreachable): submission consent is bound to user intent, so a redispatch is a user action — the Pending Payments detail's Resume — never a background retry. The automation traded away is thin: exact stored bytes, same endpoint only ("Never grants first dispatch … or endpoint failover"), so auto-rebroadcast would silently re-move money without buying failover. Consequence: stuck payments surface via the recovery report and the chip at boot instead of healing themselves; do not "fix" the missing `rebroadcast` field without re-deciding this.
